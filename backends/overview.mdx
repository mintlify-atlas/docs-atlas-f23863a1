Mirror Fit ships three independent FastAPI backends, each serving a distinct AI function. All three run on a single shared GPU — the project targets an AWS g5.xlarge instance with an NVIDIA A10G (24 GB VRAM). The face-swap backend handles avatar management, static and live face swaps, voice transform, lipsync, and garment try-on proxying. The live try-on backend streams diffusion-based garment generations over WebSocket. The InstantID backend generates photo-realistic face renders that transfer an avatar's identity onto a user's live webcam expression.

## Shared GPU Architecture

All three backends share a single NVIDIA A10G GPU with 24 GB of VRAM. Because the A10G is shared, loading all three simultaneously constrains per-backend VRAM headroom. The `start_all.ps1` script at the project root manages the process lifecycle — it starts each backend in a separate hidden process, redirects stdout/stderr to `C:\logs\<name>.log` and `C:\logs\<name>.err.log`, and only starts a backend if its port is not already bound (safe to re-run; use `-Force` to restart a running backend).

The tryon backend calls `_log_gpu()` at load time to record available VRAM so that allocation failures (which would otherwise produce a silent exit with no traceback) are diagnosed from the log. Refer to [PROGRESS.md](https://github.com/indwar7/Mirror_Fit/blob/main/PROGRESS.md) for observed VRAM behaviour — when face-swap and live-portrait are already resident, the tryon backend's model load happens against reduced headroom.

If you want to run the InstantID backend on the full 24 GB (for example when demoing the photo-real mode exclusively), set `LUCY_MINIMAL_MODE=1` on the face-swap backend. In this mode all GPU model loads are skipped — only the voice WebSocket, demo HTML serving, and avatar catalogue endpoints remain active.

## Environment Variables

| Variable | Backend | Purpose |
|---|---|---|
| `FASHN_API_KEY` | face-swap | Server-side API key for the FASHN.ai virtual try-on proxy (`POST /fashn/run`). The key never reaches the browser; the backend holds it and polls FASHN on behalf of the client. |
| `REPLICATE_API_TOKEN` | Flutter app (passed via `--dart-define`) | Replicate API token used by `replicate_tryon_service.dart`. Passed at build time — **not** held by any backend. |
| `DECART_API_KEY` | Flutter app (passed via `--dart-define`) | Decart AI key used by `decart_tryon_service.dart`. Currently not in active use; kept for the live realtime try-on screen. |
| `HF_TOKEN` | tryon, instantid | Hugging Face access token required to download CatVTON, SDXL, and InstantID weights on first boot. Without it, the tryon backend falls back to a tier that does not mask properly. |
| `LUCY_INSTANTID_URL` | face-swap | URL of the InstantID server, used by `POST /avatars/{id}/stylize`. Defaults to `http://127.0.0.1:7861`. |

## Health Checks

Each backend exposes a `GET /health` endpoint that returns a JSON object describing which models are actually loaded, not just whether the process is alive.

<Tabs>
  <Tab title="Face Swap (7860)">
    ```bash
    curl http://localhost:7860/health
    ```
    Returns:
    ```json
    {
      "status": "ok",
      "models_loaded": true,
      "engines": { "v1": true, "v2": true },
      "optional": {
        "codeformer": true,
        "face_parser": true,
        "wav2lip": false
      },
      "v2_weights": {
        "inswapper_128_fp16.onnx": { "present": true, "bytes": 277680638 },
        "GFPGANv1.4.onnx":         { "present": true, "bytes": 340256686 }
      },
      "auto_download": true,
      "clone_mode": "normal"
    }
    ```
  </Tab>
  <Tab title="Live Try-On (8000)">
    ```bash
    curl http://localhost:8000/health
    ```
    Returns `{"status": "ok"}` when the server process is up. Model load is lazy — the model loads on the first WebSocket connection.
  </Tab>
  <Tab title="InstantID (7861)">
    ```bash
    curl http://localhost:7861/health
    ```
    Returns:
    ```json
    { "status": "ok", "engine_loaded": false }
    ```
    `engine_loaded` becomes `true` after the first WebSocket session triggers the cold load (~30–60 s).
  </Tab>
</Tabs>
