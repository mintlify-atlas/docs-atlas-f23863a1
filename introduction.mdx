Mirror Fit is a Flutter-based real-time virtual try-on platform that lets shoppers see clothes on their body through their phone camera — before buying. It replaces the guesswork of online shopping with a live AR mirror: a 30 FPS on-device pipeline detects your pose, measures your body, and drapes a scaled 3D garment over you with correct rotation and occlusion. For cases where photorealism matters more than speed, Mirror Fit also ships self-hosted GPU backends that run AI-powered face swap, diffusion-based garment generation, and AI twin video — all without a single paid API call.

## Core Technologies

Mirror Fit is built entirely on open-source tooling. No vendor lock-in, no metered inference APIs.

| Layer | Technology | Role |
|---|---|---|
| **Mobile framework** | Flutter / Dart (`sdk: ^3.10.1`) | Cross-platform app, camera stream, rendering |
| **Camera stream** | `camera ^0.12.0+1` | Real-time 30 FPS frame capture for the AR pipeline |
| **Pose detection** | `google_mlkit_pose_detection ^0.14.1` *(disabled — crashes on iOS 26)* | 33-landmark skeleton at 30 FPS |
| **Body segmentation** | `tflite_flutter ^0.12.1` *(disabled — crashes on iOS 26)* | Selfie mask for occlusion at 256×256 |
| **WebRTC streaming** | `flutter_inappwebview ^6.1.5` | WebRTC camera streaming via WebView (Decart realtime) |
| **Face swap** | InsightFace | Photorealistic face transfer for avatar generation |
| **Garment diffusion** | CatVTON (via `tryon_backend`) | Diffusion-model garment overlay for high-realism previews |
| **Backend framework** | FastAPI + uvicorn | Python GPU backends over HTTP and WebSocket |
| **State management** | `provider ^6.1.2` | Reactive state across screens |
| **3D model viewer** | `model_viewer_plus ^1.8.1` | `.glb` garment preview with pan/zoom/AR Quick Look |

## Why Open Source?

Mirror Fit operates on a strict **zero paid APIs** principle: every model weight is either downloaded from Hugging Face or bundled in `assets/ml_models/`, every GPU workload runs on a self-hosted machine, and the codebase is MIT-licensed.

- **Self-hosted GPU backends** — The face-swap, try-on, live-portrait, and AI-twin services each run as an isolated FastAPI process on a single NVIDIA GPU box. `start_all.ps1` starts only the services that are down, leaving active sessions untouched.
- **On-device ML** — The AR pipeline is architected for on-device pose detection (MLKit) and body segmentation (TFLite with GPU delegate); both packages are currently disabled pending an iOS 26 compatibility fix. All per-frame fitting math is pure Dart — no network calls in the hot path.
- **MIT license** — Fork it, extend it, ship it. The full pipeline — from `pipeline_types.dart` to the Python diffusion server — is available without restriction.

## Project Components

Mirror Fit is composed of four distinct systems that work together:

1. **Flutter App (`lib/`)** — The mobile front-end. Internally named `lucy_tryon` (app title: `LUCY`), it hosts the real-time AR pipeline (`lib/ar_tryon/`), original try-on screens, and WebView-based Decart realtime streaming. Entry point: `lib/main.dart`.

2. **Face Swap Backend (`face_swap_backend/main.py`)** — A FastAPI server providing static face swap, live WebSocket swap, avatar catalogue management, and a voice-transform endpoint. Powered by InsightFace, runs on the shared conda environment at port 7860.

3. **Live Try-On Backend (`tryon_backend/server.py`)** — A WebSocket diffusion server that takes a user frame and a garment image and returns a composited result using CatVTON inpainting. Runs at port 8000; requires `HF_TOKEN` to pull model weights from Hugging Face.

4. **ML Scoring Modules** — The `fit_score` and `returns_risk` Python modules compute garment-to-body fit quality and pre-purchase return likelihood from body dimensions and garment specifications.

<Note>
  Camera-dependent features — real-time AR try-on, live face swap, pose detection — require a **physical Android or iOS device**. The iOS simulator and Android emulator do not expose a real camera stream to Flutter's `camera` package. Connect a device via USB or wireless ADB before running `flutter run`.
</Note>
